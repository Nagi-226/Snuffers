## 二、当前实现架构（rifle_controller.gd，动它之前必读）

```
_ready 顺序（顺序即不变量，错一步就坏）:
  1. _align_native_arms()      ← 臂组装对齐到武器骨（yaw180 基矩阵+弹匣骨定位，位置无关解算）
  2. _arms_placed 采样          ← 对齐结果存底，之后每帧 node.transform = _pose_extra × _arms_placed
  3. _measure_left_arm()       ← Run姿势实测上臂/前臂骨长（IK求解用）
  4. _pose_pending = true      ← ⚠️ 基座旋转与左臂姿势【不在此处施加】
  5. motion start 采样          ← 未旋转状态，与 _process 公式 E⁻¹ 修正同基
  （player_controller._ready 的 ADS 标定随后运行——它必须量到未旋转=开镜态瞄具位，
    这就是步骤4不能提前的原因；违反则 ADS 枪身整体偏左，2026-10-24 实机踩过）

_process 每帧:
  - _pose_pending 首帧补施 _apply_pose_rotation() + _pose_left_arm_mainstream()
  - ADS 插值: _aim_weight 4/s 平滑 → 联动基座旋转收放 + 左臂姿势重摆
  - 枪身 = _pose_extra × _weapon_home × start⁻¹ × motion()   ← E⁻¹ 修正防旋转双重计入
  - 弹匣 = _mag_home × start⁻¹ × _magazine_motion()          ← 同款修正
```

### 不变量（违反任意一条 = 回归）
1. **基座旋转（HIP_POSE_YAW 0.26 / PITCH 0.05）只能乘在 ViewModel 的两个同源子节点**（EM68A/ArmsEM68A），绝不能放 ViewModel 父节点——基类 `_update_view_recoil` 每帧绝对写 `ViewModel.rotation.x`。
2. **两子节点必须同旋转同原点**（tscn 里 position 一致），否则枪臂错位。
3. **换弹期间姿势改写跳过**（`if not _is_reloading`），臂归原生剪辑所有；换弹结束 `_reset_reload_visuals()` 重放 hold + 重摆姿势。明日改换弹时保持这条边界。
4. **骨架骨轴 = basis.y**（实测肩→肘夹角 0.00001°）；`BoneTwist_03.L` 与前臂**共位**（零向量尖端，不能作旋转尖端——v1 左臂静默失效根因）。
5. **手（IK_Hand_Cntrl_L 独立子树）必须定位到链端**（fore.origin + basis.y×前臂长），不能定位到理想目标——否则够不着就断腕悬浮。
6. **目标坐标必须先探针量几何**（`tools/probe_left_arm.gd` 会打印枪身子网格 AABB），不许拍脑袋——v17 左手悬空 6cm 就是拍出来的。

## 三、工具与验证规程（姿势/视图模型类改动的标准流程）

1. **骨架探针** `godot/tools/probe_left_arm.gd`:
   `godot --headless -s tools/probe_left_arm.gd --path .`
   输出: 腕缝（须<0.1mm）/ 手到目标 / 掌轴对枪口 / 枪身各子网格 AABB。改姿势先跑它。
2. **vm-shot 取证**（窗口跑，headless 无渲染）:
   `godot --path . res://scenes/levels/street_playable.tscn -- --vm-shot <out.png> [pistol] [ads] [fill] [reload] [reload_seconds X]`
   ⚠️ **证据有效性**: 日志 `grep -c "SCRIPT ERROR"` 必须为 0 且 `NATIVE_ALIGN2` 打印在案——曾有无控制器挂载的"成功"截图假象。
3. **视觉分析双问法**（4_5v 分析器）: 指标式（位置%/角度）+ **找茬式**（"宁可多报不可漏报"）必须都用——指标全绿曾三次虚报达标被机主当场否决。HUD 红点永远画在屏幕中心，量实体金属件。
4. L1: `powershell -NoProfile -ExecutionPolicy Bypass -File godot/tools/check.ps1`

## 五、⏳ 明日主任务：换弹匣动作修复（混乱脱节）

### 现象（机主 2026-10-24 晚定调）
"换弹匣动作很明显是混乱脱节"——手、弹匣、枪身三者不协调。

### 现行换弹机制（明日入手点）
- 剪辑: `Armature|Arms_FPS_Anim_Reload_Fast` 重定时到 `weapon_data.reload_time`（2s），注册为 `&"reload"`。
- 期间: 武器骨整驱枪身（含大角度翻转——**混乱感主要来源嫌疑**），弹匣骨驱 `em68a_magazine` 节点，左臂归剪辑所有（v1 遗留：剪辑里左手回到作者高位托枪，与日常姿势跳变=**脱节感来源嫌疑**）。
- 结束: `_reset_reload_visuals()` 回 hold + 重摆左臂（0.15s 淡入淡出缓冲）。

### 初步假设（明日先取证再动手）
1. 剪辑 authored 枪骨运动会带动 EM68A 整枪大摆（原生动画给原作者的枪设计的动幅，套 EM68A 上可能过猛）。
2. 弹匣枢轴不匹配: EM68A 弹匣 GLB 规范是"枢轴原点在顶部面心"，骨骼弹匣动画可能按底部/侧面枢轴 authored → 弹匣抽插轨迹错。
3. 剪辑左手与主流左手（榴弹筒后段）在进出换弹时跳变。
4. 换弹中枪身带着 HIP 基座旋转量翻搅（_pose_extra 换弹期间冻结，剪辑动幅叠加其上）。

### 取证步骤（明日第一步，别直接改）
1. vm-shot 抓换弹时间序列（reload_seconds 0.3/0.6/0.9/1.2/1.5/1.8）逐帧找茬式审查，定位"乱"与"脱节"具体在哪个相位。
2. 探针改造（或临时打印）: 换弹期间逐帧打印武器骨/弹匣骨局部位 vs hold 基线，量化动幅。
3. 对照 Cransh 原生枪（arms glb 自带枪模被我们隐藏了）的换弹原设计——可临时把 arms 自带枪 mesh 显出来截一帧对照 authored 意图。

### 约束红线
- **不得破坏已验收姿势**: hold/ADS 两态 + 左臂 v2 链闭合 + 基座姿态全部保持; 换弹修复只在换弹窗口内动。
- 动 weapon_bone 驱动公式前先读 §二 不变量 1/3 与 E⁻¹ 修正。
- 手枪换弹若被牵连回归，同标准修复。
