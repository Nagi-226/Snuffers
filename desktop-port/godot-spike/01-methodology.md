## 0. 定位与效力（先于一切）

1. **效力层级**：`AGENTS.md`（十荣十耻/团队边界/设计约束）> 本文件。冲突时以 `AGENTS.md` 为准，本文件自行失效对应条目。
2. **适用人**：**仅蜂后（Orchestrator）**。工蜂派单已含原子任务，**工蜂不加载本文件**，派单中也不得夹带本文件内容。
3. **吸收原则**：只收 `AGENTS.md` 未覆盖的「判断格式」，不重复已有行为约束；只取操作规程，不带语录、不带修辞外壳。
4. **调用纪律**：一个场景最多调用一件武器；不能明显改善判断质量就不调用；不为形式完整而机械走流程。

## 3. 吸收的五个标准格式

### 3.1 矛盾分析裁决表（用于一切「待裁决事项」）

```
## 裁决事项：[一句话]
### 矛盾清单
- [A 立场/方案] vs [B 立场/方案]（附各自事实依据：文件:行号）
- …（次级矛盾）
### ⭐ 主要矛盾
[哪一个]——理由：解决了它，[X] 和 [Y] 矛盾随之缓解。
### 性质判定
[对抗性：必须取舍 / 非对抗性：共同目标下的分歧，勘误即可]
### 裁决结论
采 [A/B/折中]，理由：①②③（每条附事实依据，禁止"我觉得"）
接下来我将：[具体动作清单，含责任域]
### ⚠️ 需监控
- [次要矛盾 X] 是否上升为主要矛盾（监控信号：……）
```

**填写规则**：事实依据必须可定位（源码行号/文档条目/命令输出）；「非对抗性」裁决以勘误收尾，不追责；根因若指向派单方（蜂后）措辞歧义，必须记入本节并作为后续派单教训。

### 3.2 门禁审视报告（G1–G4 复盘用，替代散点式总结）

```
## 门禁审视报告（G?）
### 原定目标与验收标准：[复述计划条目]
### 完成情况：- [x]/[ ]（未完成项附原因）
### 发现的问题
| 严重程度 | 问题（具体行为+文件:行号） | 根本原因（必须指向方法论失误） | 改进建议 |
| 必须改正 / 应当改正 / 建议改进 | … | … | … |
### 做得好的地方：……
### 下次重点关注：……（直接进入下一 Sprint 派单上下文）
```

**填写规则**：「根本原因」禁止停留在现象层，必须指向方法论失误（跳过了调查？未验证？派单歧义？范围失控？）；问题表为空时必须写明「未发现问题，原因是……」。

### 3.3 拉伸项解锁·流寇主义三问（§5 拉伸项评审闸，逐项回答否则不解锁）

1. 上一个切入点（当前门禁）已验证稳固了吗？（未稳固不得扩展）
2. 这次扩展是从已验证根据地自然延伸吗？（跳跃式扩展 = 流寇，拒绝）
3. 新增内容可复用、可登记（ATTRIBUTION）吗？（一次性内容不算建设）

### 3.4 多源反馈综合（G4 A/B 判定用）

```
信息源清单：①机主试玩打分 ②Tracy 性能数据 ③§7 参数表核验 ④任务链跑通记录
各源一致之处：……（可信事实）
各源矛盾之处：……（调用 §3.1 裁决表处理）
信息缺口：……（标注需补充验证项）
综合判断：……（依据 = 源①+源② 共同指向……）
```

### 3.5 疑难 bug 攻坚五环（十荣 #10 的完整化：补假说与证伪回退）

```
调查（现象/条件/已排除项，精确描述问题）
→ 假说（"如果 X 则应观察到 Y"）
→ 验证（最小复现，一次只改一处）
→ 证伪回退（假说不成立 → 回到假说步，不得加 workaround）
→ 审视（§3.2 格式复盘，根因归档）
```
