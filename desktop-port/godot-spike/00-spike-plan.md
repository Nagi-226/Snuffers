# 《熄烛者》（Snuffers，原《废墟突围》）Godot 重制 Spike 作战计划

> 版本：v1.0 · 2026-07-15 · Orchestrator 制定
> 调研输入：5 路探索代理（玩家手感 / 武器战斗 / 敌人进程 / 资产脚手架 / Godot 技术事实）
> Spike 周期：**D1 = 2026-07-16（周四） → D14 = 2026-07-29（周三）**

---

## 1. Spike 目标与判定问题

**唯一核心问题：Godot 能否做出不劣于（且优于）网页版手感的第一人称射击体验，从而成为项目主线？**

Spike 不是做完整游戏，而是验证一条**最小手感闭环**：

```
移动/瞄准手感 → 步枪击杀步兵 → RPG 摧毁碉堡 → 呼叫直升机 → 60 秒坚守 → 撤离结算
```

判定方式：**A/B 对照** —— 同一台机器上，网页版（Electron 版亦可）与 Godot 版并排试玩，按 §8 验收清单打分。

| 判定结果 | 后续行动 |
|---|---|
| ✅ Go（手感达标） | Godot 升为主线（dev_godot 转正），Electron 版维持为发布壳，资产策略文档全面启用 |
| ⚠️ Conditional Go | 锁定差距清单，追加 1 周定向攻坚再判 |
| ❌ No-Go | 保留 Electron 主线，spike 成果（参数表/资产/工具链）归档，零沉没污染 |

## 2. 技术栈决策（决策记录）

### 结论：**Godot 4.6.2 stable + 纯 GDScript**

| 决策因子 | GDScript | C# (.NET) | 裁决依据 |
|---|---|---|---|
| 本机 .NET SDK | 不需要 | **缺失（需装 .NET 8+，Android 导出要 9+）** | 实测：本机 `NO_DOTNET_SDK` |
| 迭代速度（spike 生命线） | 保存即生效，零编译 | 每次改导出变量/信号须重建程序集 | Godot 4.6 官方文档 "Current gotchas" |
| Web 导出（项目原始平台） | ✅ | ❌ Godot 4 全系不支持 | 官方 C# basics 文档明示 |
| Android/鸿蒙路线（dev_mobile 远景） | ✅ 成熟 | ⚠️ 4.2 起 experimental | 官方文档 + 社区实测 |
| 现有 JS 代码迁移成本 | 低（同为动态语言，逻辑近 1:1 直译） | 高（需类型化重写） | 调研：index.html 3782 行内联逻辑 |
| 脚手架语言 | Jeh3no 武器系统 100% GDScript；官方 TPS demo 15×.gd / 0×.cs | — | 本地实测 |
| 性能分析 | **4.6 新增 Tracy 原生支持 GDScript**（G4 门禁的性能取证工具） | — | 4.6 beta1 官方博客 |
| 性能风险 | 本游戏规模（低模、≤20 敌）远低于 GDScript 瓶颈；渲染/物理跑在原生层 | 无实际收益 | — |

**可逆性声明**：若后续规模化出现热点路径，可局部引入 C++ GDExtension；spike 期间纯 GDScript，不混编。

**被否决方案**：C#（编译链缺失+移动端 experimental）、继续 Three.js 深挖（3D 管线与资产生态天花板，正是 spike 存在的原因）、Rust/C++ 重写（与验证目标无关）。

## 11. 决策记录补充（2026-07-21 机主裁决，效力等同本计划正文）

### 11.1 穿墙射击处置：采 A 方案「保机制补表现」

- **背景**：碉堡机枪 `alerted=true` 常态 + `alerted` 开火判定绕过距离/视线（web L958/L1823 原版行为，忠实复刻），叠加夜战过暗、无曳光/枪口火光/受击方向指示，造成「看不见敌人却被连续攻击」的灵异体验。
- **裁决**：机制保持网页版基准不动，**补表现层三件套**：敌人弹道曳光、枪口火光、受击方向指示弧。
- **落地**：G2 后第一批施工——曳光/枪口火光归 W3 发射 + W2 结构参考（Jeh3no 特效场景）+ W5 受击方向弧（HUD 域）。
- **复评**：三件套上线试玩后，若穿墙射击本身仍影响体验，再启 C 方案（alerted 保留索敌、开火仍受射程限制）裁决。

### 11.2 双模式地图：白天 + 黑夜

- **裁决**：同一战场做**白天/黑夜双模式**，美术风格统一对齐机主提供的参考图（贴图化军事风，非低模卡通风）。
- **黑夜模式**：保留夜视仪核心机制；**夜视仪键位定为 N 键**（网页版为 V，Godot 版按机主要求改绑 N）；夜视仪开启时使用专用夜视画面素材/后期效果（绿色磷光风）。
- **落地**：模式切换与光照/后期切换的功能逻辑进 Sprint 3（W4 关卡域 + W1 键位 + W5 夜视画面）；配套美术素材（白天贴图场景 + 夜视画面效果）按 §11.3 排期。

### 11.3 美术排期与质量优先级

- **裁决**：美术风格化（双模式贴图素材、夜视画面素材）**放在 G4 判定之后**全面启用（资产策略文档既定路线）。

- **灰盒纪律不变**：任何 Agent 不得在 spike 期间擅自引入美术资产替代功能施工。
