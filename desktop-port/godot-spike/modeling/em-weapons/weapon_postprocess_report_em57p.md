拆分方式：**顶点组承载部件标签 → `bpy.ops.mesh.separate(type='SELECTED')` 级联 3 次**。全程只做"分组/分离"，
**不移动、不合并、不重算任何顶点/法线/UV**；4 个对象各自 `transform_apply`（输入为恒等变换，实为 no-op，仅为满足"应用全部变换"并留证）。

### 3.2 阈值（逐武器实测标定，禁止跨武器套用）

坐标系米制（枪口 +Y、枪托 -Y、上 +Z），判定顺序 **瞄具 → 弹匣 → 引针模块 → 其余归 body**：

```python
# EM-57P（scripts/weapon_postprocess.py:69-91）
if lo[2] > 0.13 and -0.16 < cy < 0.06:                      # optic
elif hi[2] < -0.145 and -0.38 <= cy <= -0.14:              # magazine
elif cy > 0.20 and 0.01 < hi[2] < 0.07 and lo[2] > -0.06:   # laser_module
else: body
```

标定方法（派单 L20 要求）：**"规则假设 → 高亮渲染 → 逐集合隔离渲染" 迭代 4 轮**，每轮 Blender 起停约 25 s。
中间产物与判读证据保留在 `desktop-port/godot-spike/modeling/em-weapons/renders_em57p/`（`colors/` 分量上色、`hl/` `hl2/` 规则高亮、`iso/` 隔离对照、`detail/` 特写）。

### 3.3 三处判断（都是模型本身的性质，不是凑数）

1. **弹匣：本模型没有独立插入件几何。** 30 发弹匣与握把**齐平**，弹匣体就是握把下段的壳体。实测依据：在握把内部搜索"窄件"（整体落在 `Y∈[-0.32,-0.16]`、`Z∈[-0.25,-0.08]` 内）**命中 0 个连通分量**；握把侧板是一整块连续壳体（隔离渲染显示为整片面），底部只有一块贯穿全宽的底盖板。
   → 取 **M3 集合**（下段整块壳体 57,307 tris + 底盖板 10,274 tris）为 `magazine`。隔离渲染确认拆走后**握把侧板、前后握把条、扳机护圈仍在**，等价于"抽出弹匣后只剩弹匣井"。不作"随手抓几个件凑数"的处理。
2. **引针模块：取前段下挂组件**（上下壳体 + 底面导轨段 + 前部圆筒发射器 + 端盖），隔离渲染确认其为一个自发光的整体块，且与护木/枪管主体分离干净。用 `hi[2] > 0.01` 把最底部那条导轨排除，避免把护木底轨带走。
3. **机瞄/导轨不划入瞄具**：`optic` 只取顶面 z>0.13 且位于镜桥区间的反射式瞄具（18 个分量）；机匣顶部导轨、前后折叠机械照门留在 `body`。理由与第 14 号单一致——机械照门是机匣固定件，剥离会让机体失去瞄具基准且不可拆换。

### 4.3 对照实验：+39 顶点与拆分无关（关键归因）

| 实验 | 顶点 | 三角面 | 节点 | 文件 |
|---|---|---|---|---|
| 输入 `em57p.glb` | 708,475 | 1,370,580 | 1 | 53,740,660 B |
| **导入后立即导出（零拆分）** `em57p_roundtrip_control.glb` | **708,514（+39）** | 1,370,580（+0） | 1 | 53,741,776 B |
| 拆分后输出 `em57p_viewmodel.glb` | 708,514（+39） | 1,370,580（+0） | 4 | 52,086,172 B |

→ **+39 完全由 Blender glTF 导出器的往返行为产生，与拆分操作无关**（零拆分也 +39，且数值完全相同）。

机制（与实测精确吻合）：本模型有 **13 个平坦着色面**（`shade_smooth` 面 1,370,567 / 总面 1,370,580）。glTF 顶点必须携带单一法线，平坦面要求其 3 个角点各拆出一份"面法线"顶点：**13 × 3 = 39**，与增量**精确相等**。em68a 全 1,464,017 面均为平滑着色 → 差值 0，正好解释了第 14 号单为何没有这个现象。
+39 在四个对象上的分布：`body +27 / optic +9 / magazine +3 / laser_module +0`。

### 4.4 结论
**几何零改动成立**：三角面数、三角面集合与绕序哈希、每位置顶点位置、UV 偏差为 0 全部通过；两处"不等"分别是①导出器对 13 个平坦面的法线必需复制（+39 顶点，不改任何面/位置）②校验器把 glTF 默认值当差异的伪阳性。**没有减面、没有重拓扑、没有顶点合并、没有法线重算、没有贴图重压缩或重采样。**

## 6. 未解决问题

1. **P2 文件级 +39 顶点**。派单要求"顶点数相等"，严格按文件级计数**不满足**。已用零拆分对照实验证明是 Blender 导出器行为（§4.3），并非拆分引入；根因是 13 个平坦面。**若蜂后要求严格达标**，可选：① 把 13 个平坦面改为平滑着色（**会改变视觉结果，违反 L29，我不建议**）；② 接受文件级 +39 并在验收口径上明确"以 Blender 侧 / 位置组为准"；③ 换用 `export_normals=False` 由引擎重算法线（**同样改变视觉，不建议**）。**我倾向方案 ②**，等蜂后裁决。
2. **P2 法线往返微漂**：max 0.349°、mean 0.0070°、p99.9 0.0592°；46,047 个顶点因位置组重排无法配对，无法逐点比较。与 em68a 同源（第 14 号单已挂账）。影响评估：0.35° 在 1080p 近距高光下不可见，不构成视觉回归；但严格讲不是"逐顶点一致"。
3. **P3 校验器「材质语义」伪阳性**：输入显式 `normalTexture.scale: 1`、输出省略。建议校验器按 glTF 规范默认值归一后比较，下一位可改。
4. **P3 images 数组顺序变化**：输入 `[Color, ORM, NormalGL]` → 输出 `[NormalGL, Color, ORM]`。内容（sha256）完全一致，仅索引顺序变化，Godot 按材质引用解析，不受影响。
5. **P3 四对象共享世界原点**：四个 MeshInstance 的 transform 均为 identity，origin 都在模型中心。Godot 侧做换弹/抛壳动画时，需按 `magazine` 的 bbox 中心（Y−0.27 / Z−0.21 附近）自行取枢轴，不要假设对象原点在弹匣上。

## 9. 复跑与移植注意

1. **必须传绝对路径**：执行中继的 `runner.gd` 不切换 cwd，相对路径会在中继目录下找不到文件。
