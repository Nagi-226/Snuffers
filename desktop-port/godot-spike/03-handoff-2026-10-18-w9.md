## 3. 给下一棒的注意事项

1. **55 MB 级 GLB 都在工作树里**（`em57p.glb` / `em68a.glb` 已由机主裁决入库为 `64d67d7`；`*_viewmodel.glb` 的枢轴版改动**未入库**）。不要 `git add .`，只精确 add 脚本 + 报告 + JSON。
2. **不要覆盖已交付的输出**：`weapon_postprocess.py` 默认输出到输入同目录的 `<stem>_viewmodel.glb`，重跑会覆盖。要重跑请显式传第二个参数；第 17 号单的 `rebuild_viewmodels.py` 是**故意覆盖**同名 viewmodel 的（派单要求），它只在备份缺失时才建基线。
3. **执行通道**：本机 DSH 的 `pwsh` 工具 100% 崩溃（退出码 3225794 / 0xC0000142），唯一可用通道是 `modeling/tools/subproc/`（`runner.gd` + `cmd.json`，由 `godot_run_headless` 拉起，读同目录 `cmd.json` 的 `{exe,args,timeout}` 并回传 `last.log`）。该目录**故意保留且不入库**。
   - 坑 1：`runner.gd` **不切换 cwd** → 命令里的路径必须绝对。
   - 坑 2：子进程 stdout 是 GBK，中继按 UTF-8 解码会出乱码（数字/路径不受影响，完整日志读 `last.log`）。
   - 坑 3：`cmd.exe` 批处理文件若用 LF 换行会报 `'xxx' 不是内部或外部命令`，**别用 .bat**，直接让 python 的 `subprocess` 编排。
   - 坑 4（第 17 号单新发现）：`godot_run_headless` 单次调用**约 130 s 硬上限**；`OS.create_process` 与 `DETACHED_PROCESS` 起的子进程都会随 Godot 一起被杀（作业对象带走）→ **把工作切成 <110 s 的同步调用**（`rebuild_viewmodels.py --steps` 就是为此）。
   - 坑 5：Blender 进程没退干净时再导出会 `OSError: [Errno 22] Invalid argument`（文件被占用）；用 `taskkill /F /IM blender.exe` 清场。本机**没有 wmic**（`FileNotFoundError: [WinError 2]`），用 `tasklist` / `taskkill`。
   - 坑 6：**不要用「排序后比对」或「1 nm 哈希」判几何相等**。前者会在近似重复点上把 float32 抖动放大成 8.3 cm 假差异，后者比顶点存储精度还细。正确口径 = **逐顶点索引比对 + 1 µm 容差**。
4. **工作树里有别人的未提交改动**（51 个 `godot/assets/**/*.import` + `desktop-port/godot-spike/07-snuffers-art-design.md` 及其未跟踪文件），**不要碰、不要 commit**。
5. **渲染目录 `renders_em57p/` 体积大且不入库**：`colors/` `hl/` `hl2/` `iso/` `detail/` 是标定证据，`whole_*` `part_*` `body_rest_*` 是报告引用的成品对照图。
6. **新增武器标准流程**（已脚本化）：① `PROFILES` 加档 + 写 `_classify_<stem>` + 标 `pivot_part`；② 六视角转面渲染确认朝向与布局；③ top-N 分量上色定位大件；④ 规则高亮 → 逐集合隔离两轮收敛阈值；⑤ 跑管线；⑥ `verify_glb_identity.py` 独立校验；⑦ 写 md/json 报告；⑧ em68a 回归 sha256 必须不变。
7. **别把 em57p 的阈值套到新武器**：本模型弹匣与握把齐平（无独立插入件几何），阈值是绑这把枪的握把尺寸标定的。
8. 起 Blender 必须带 `--factory-startup` 和 `--python-exit-code 1`。
9. **弹匣枢轴的语义边界**：枢轴只给"面心点位"，不含弹匣轴向；若换弹动画需要沿弹匣轴线方向拔插，还要在 Godot 侧按弹匣 AABB 主轴自己算方向（或再发一张派单加 `pivot_axis`）。
